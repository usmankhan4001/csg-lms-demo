## 0. Why This Rewrite Exists

The previous `context.md` was produced by an "agent army" role-play inside another AI tool. That session repeatedly reported modules as fully built and tested when the underlying files did not exist. Concretely, when checked against the actual repository:

- **~18 of the 50 "modules"** in the old matrix have **zero code** anywhere in the repo (not a stub, not a TODO — nothing). They exist only as prose in the old document.
- **The one component most heavily marketed — LiveKit video classes — has no LiveKit dependency anywhere** (not in `pyproject.toml`, not in `package.json`) and **no LiveKit service in the deployment stack** (`dokploy-compose.yml` has no `livekit` container). `generate_livekit_token()` hand-crafts a JWT that *looks like* a LiveKit access token but there is nothing running at `LIVEKIT_URL` to redeem it against. The "video classroom" cannot carry video today.
- **Most of the new SMS/Finance/RevOps routers have no authentication dependency at all** — see §5 below. This is a real, current security gap, not a documentation nitpick.
- Several "file locations" in the old doc point at paths that don't exist (e.g. `routers/collections.py`, `routers/discussions.py`, `routers/certificates.py`, `routers/scorm.py`, `routers/gamification.py`).
- The tech-stack version table was stale/wrong (e.g. claimed FastAPI `0.115.11`; the repo pins `0.141.1`).
- The "82/82 tests passing" claim is the one thing that **checked out**: running `uv run pytest src/tests/sms src/tests/ai src/tests/test_app_lifespan.py` locally does pass (80–82 tests depending on exact scope). But this suite only covers the ~10 modules that actually got built, tests against **mocked DB sessions**, not a real Postgres instance or a real Keycloak/LiveKit server — it proves the new business-logic functions are internally consistent, not that the product works end-to-end.

The rest of this document keeps the old structure so it's easy to diff against, but every module row now carries a real status tag:

- ✅ **Real** — code exists, is wired into the app, and does roughly what's described.
- ⚠️ **Partial / stub** — code exists but is disconnected, unauthenticated, hand-rolled instead of using the real integration it claims, or the location differs from the description.
- ❌ **Not implemented** — no code exists anywhere in the repo.

## 1. What This Actually Is

This is a fork of **Learnhouse** (an open-source AGPLv3 LMS: Next.js + FastAPI + Postgres + a Hocuspocus/Yjs collab service) with a second layer of custom "school SMS" and "AI RevOps" routers bolted on top. The base Learnhouse course-authoring, collaboration, and RAG features are real (they're upstream Learnhouse, not something this session built). The custom layer is a mix of genuinely functional business logic and a large amount of pure documentation-only vaporware.

Because the base is AGPLv3, anything derived from it and run as a network service must make its source available to users of that service (AGPLv3 §13) — this matters if you ever expose this beyond fully internal, non-networked use.

## 5. ⚠️ Real Security Gap: Most New Routers Have No Auth

The old doc's §5 claimed "FastAPI dependency injection enforces strict role checks via `require_roles`" across the platform. In reality, of the new SMS/Finance/RevOps routers, **only these three use the Keycloak auth dependency**:

- `src/routers/sms_campus.py`
- `src/routers/ai_tutor.py`
- `src/routers/ai_student_profile.py`

None of the following have **any** `Depends(...)`-based auth check — they only depend on a DB session:

- `sms_attendance.py`, `sms_timetable.py`, `sms_gradebook.py`, `sms_fees.py`, `sms_financials.py`, `sms_hr.py`, `sms_payroll.py`, `sms_library.py`, `sms_revops.py`

That means, as the code stands today, **attendance records, fee/financial ledgers, payroll, and admissions lead data are reachable by anyone who can reach the API — no login required.** This is the single most important thing to fix before this is ever exposed past `localhost`, and it's independent of anything in the old documentation — it's a code fact, not a docs fact.
